# Changelog

## Unreleased

### Added

- **Discord**: the Player shows "Listening to Mornye" on your Discord profile, with the song, artist, album, elapsed time and the album cover (looked up on Apple Music, only when the artist matches). It talks to the Discord desktop app on the same computer, with no Discord SDK, and waits while Discord is closed. Set up in Settings › Player › Discord with your own application ID from the Discord Developer Portal. Desktop only.
- **Last.fm scrobbling**: "Scrobbling now" while a song plays, and a scrobble once half of it or four minutes has been heard, never for a song under thirty seconds. Seeking ahead does not count as listening. You sign in with your own API key and shared secret through Last.fm's approval page, and they are kept in a file only your user can read. Scrobbles that cannot be sent wait and are tried again. Settings › Player › Last.fm. Desktop only.
- **Mornye Link and Mornye Connect**: pair the Mornye phone app with the computer with a PIN (Settings › Player › Mornye Link), so the phone plays the library through the Subsonic API with its own key. With Connect, one device plays and the others control it or take playback over ("Play on"). In `--web` an admin can also let the server play through its own speakers (`MORNYE_CONNECT_SERVER_SPEAKER=1`).
- **Cast to DLNA/UPnP and FCast receivers** on the network from the Player (desktop).
- **Personal Home and listener profile**, made from what the Player has played: recommendations, mixes from the library, Quick Play, pinned items, "Finish your collection" and "On repeat", reordered or hidden with Edit Home. Stats › Listening shows listening time, streaks, top artists, albums and songs, taste, time of day and listener types.
- **The music look**: Settings › General › Interface Style › Music is a music-app look with the recommendations on Home. Console is still the default.
- **Settings › Storage** shows what Mornye keeps on disk and in memory, and clears what can be rebuilt (caches, thumbnails, decoded copies, scan indexes). Settings, history and extensions are shown but never cleared.
- **Parametric equalizer** for the native engine: up to 20 peak and shelf filters with a preamp, imported from and exported to AutoEQ.
- **Media keys and Now Playing on macOS with the native engine**, and the keyboard's media keys control the Player with both engines.
- **Lyrics translations saved as `.mlrc`**, the Mornye app's lyrics file, next to the song, and read back from there. The song's own tags are not touched.
- **Share Link**: the song's links on other services, found by ISRC or by title and artist.
- **Imported playlists follow their source**: songs added to the provider's playlist are appended to the Player playlist, and songs you removed stay removed.
- **Richer Apple Music** artists, albums and search, with play counts by ISRC.
- **The library in the sidebar**: Recently Added, Artists, Albums, Songs and each playlist, and the arrow keys move around the sidebar and the Player.
- **Canvas and animated artwork in the Player**: a track's Spotify Canvas plays in the cover's place (switch in Settings › Player), and the album's animated artwork plays in the full-screen player.
- **Artist photos** on library artist cards and the artist page.
- **Save .m3u8** rebuilds a playlist's file from the library without downloading anything.
- **Fix Local Files**: a search box to find one song in the list, and a list that stays responsive on folders of thousands of files.
- **`{explicit}` filename placeholder**: ` (Explicit)` for an explicit track, nothing otherwise (#290).
- **Year in album folder names**: `--album-folder-year` (also in Settings, the TUI, profiles, `MORNYE_ALBUM_FOLDER_YEAR` and REST) names the folder "Flower Boy [2017]", so two editions no longer share one. Off by default (#291).
- **High-pass TPDF dither** for bit-depth caps: `--transcode-dither tpdf_hp` moves the noise to high frequencies, where it is harder to hear.
- **Custom endpoint for Amazon Music**, checked like the Tidal and Qobuz ones.
- **`errors.log`** in the cache folder keeps every error with its full traceback (rotated at 1 MB) for the GUI, the web server and the CLI. The console is unchanged.
- **`MORNYE_FOLDER_DIALOG=builtin`** picks the download folder in the page instead of the system dialog, for kiosk setups where a second window would open behind the app.
- **Desktop app downloads**: every release now also ships the GUI packaged as an application — `Mornye-macOS.dmg` (Mornye.app, Apple Silicon), `Mornye-Windows-Setup.exe` (a per-user installer with a Start menu entry and an uninstaller) and `Mornye-Linux-x86_64.AppImage`. They open the window on a double-click, where the command-line binaries, which are still published, print their help. Run from a terminal with arguments, the app's binary is the normal command line. Without a console, start-up output and errors go to `~/.mornye/.cache/desktop.log`. The builds are not code-signed yet, so macOS and Windows ask to confirm the first launch.
- **Subsonic / OpenSubsonic API** for `--web`, under `/rest`: Symfonium, Feishin, DSub and other Subsonic apps browse, search and stream the library, with stars, play counts, playlists and a saved play queue kept on the server. Off until `MORNYE_SUBSONIC_PASSWORD` (or `MORNYE_SUBSONIC_API_KEY`) is set. See [Subsonic](docs/guide/subsonic.md).
- **The Player keeps its library between visits**: the page opens with the stored library at once and then reads only the files that are new or changed.
- **Stats count the music from before Mornye**: files in the Player's library that Mornye did not download count in the totals and rankings, as the source "Before Mornye".
- **Templates** in [`templates/`](templates/): a one-link download script, a headless NAS sync that re-checks a list of playlists every few hours, and a systemd service for `--web`, linked from the README next to the Docker compose files.
- **Existing library folders** (#272): point Mornye at music you already have — an older library, another downloader's output — with *Existing library folders* in the GUI settings, `--library-scan-dir DIR` (repeatable) or `MORNYE_LIBRARY_SCAN_DIRS`. Playlist tracks and single tracks found there (by ISRC, tags or file name) are not downloaded again, and the playlist's M3U links to the file where it is. Albums still download in full, and a folder that is missing is skipped with a warning.
- **Direct lyrics sources**: `kugou`, `qq` and `genius` in `--lyrics-providers` now actually fetch lyrics, straight from the services. They had been offered by the CLI and the TUI without anything answering to those names. KuGou and QQ Music return line-synced LRC; Genius returns plain lyrics with every verse and chorus container kept, and uses the official API when `MORNYE_GENIUS_TOKEN` is set. All three are opt-in and also appear in the web GUI and the health check.
- **CUE sheet splitting**: `mornye --split-cue PATH` splits a single-file album (FLAC/WAV/APE…) plus its `.cue` into one tagged file per track (`--cue-format flac|alac|wav`, `--cue-output`, `--cue-dry-run`, `--cue-overwrite`, `--cue-encoding`). Cuts are frame-accurate (1/75 s); the source is never modified.
- **Persistent extension storage**: what a JavaScript extension saves with `storage.set` (tokens, sessions, device ids) now survives restarts. It is encrypted per extension under `~/.mornye/extension_storage`, with the key in the OS credential store when available (otherwise a 0600 key file). Several runtimes of the same extension add their own keys without overwriting each other's.
- **M3U/M3U8 import**: `--csv`, the GUI's CSV import and the REST endpoint now also take an M3U/M3U8 playlist. Links are kept, local files are identified by their own tags, and other entries by their `#EXTINF` line (plus `#EXTART`/`#EXTALB`) or file name; everything else goes through the same matching and unresolved-row report as a CSV.
- **AAC and Opus conversion targets**: `--transcode aac` (`.m4a`) and `--transcode opus`, also in the GUI and TUI menus. Both use `--transcode-bitrate`; Opus is capped at 256 kb/s, the most libopus accepts per channel. An AAC `.m4a` and an ALAC `.m4a` are told apart by codec, never by extension.
- **Caps for converted files**: `--transcode-max-rate HZ` and `--transcode-max-depth 16|24` (also `transcode_max_sample_rate` / `transcode_max_bit_depth` in profiles, environment settings and the Python API) bring a source above them down — the sample rate within its 44.1k/48k family, the bit depth with triangular dither — even when it is already in the `--transcode` format, in which case it is re-encoded in place.
- **SoXR resampling for MP3**: converting a Hi-Res source to MP3 now resamples within its rate family (88.2/176.4 kHz → 44.1 kHz, 96/192 kHz → 48 kHz) instead of letting ffmpeg pick 48 kHz for everything, and uses the SoX resampler when ffmpeg is built with libsoxr. Lossless targets are untouched.

### Changed

- **Quality fallback asks every service for Hi-Res first**, then goes back to the first service for Lossless, instead of stepping down inside each service.
- **The endpoint list is read locally** unless `MORNYE_CLOUD_ENDPOINTS=1`.
- **Metadata enrichment uses only the services listed** and skips files that were discarded.
- **A followed playlist's M3U follows its current listing** at every check, so songs that left the playlist or moved leave the file too (#280).
- **Long lines in the Player scroll** instead of ending in an ellipsis, except with Reduce Motion.
- The retired Amazon lyrics source was removed.
- **The sidebar slides when it folds**: Collapse and Expand now narrow and widen the sidebar in a short slide, with the names fading and the group headings folding away, instead of cutting from one layout to the other. The icons stay where they are, and the download bar follows. It is the one animation kept with Reduce Motion on: everything else stays still.
- **New look: the "studio console"** across the GUI, the web app and the terminal UI. Graphite grounds, one amber signal colour for focus, selection and the one primary action of each screen, green and red only for state, JetBrains Mono throughout, square 2–3 px corners and flat surfaces. Rules and small-caps legends replace cards and shadows; the queue, the dock and Stats draw progress as segmented meters. Every view was rebuilt on a single set of design tokens (`mornye/branding_tokens.py`, generated into `frontend/css/tokens.css`) that the TUI themes are built from too. Phones keep their bottom bar and 44 px controls.
- **Accent colours change only the signal.** Amber is the new default. Anyone still on the old default (teal, or green from before the 2026 rebrand) moves to amber once; a colour picked afterwards is kept, and now reaches every view rather than only the older ones.
- **Terminal UI:** a one-line masthead replaces the block wordmark, badges are bracketed readouts (`[HI-RES]`) instead of filled pills, panels are ruled boxes, and the console dark/light themes are the default. The theme picked with `t` is now remembered between runs (`~/.mornye/tui-theme`). History, Extensions and the other panels fit an 80×24 terminal again.
- The browser address bar, the installed PWA and the desktop window open on the new background colour, without a flash of the old one.

### Fixed

- **Collaborations stay in a followed playlist's M3U**: tracks with several artists were missed when the file was rewritten, so a 50-track playlist could come out with 16.
- **Dolby Atmos is downloaded when the stereo version is already there**: the stereo file was taken for the Atmos one. An Atmos file whose name is taken is saved as "… (Dolby Atmos).m4a".
- **REST downloads go to the account's folder and use the saved Artist/Album layout** (#288), instead of `./Downloads` with every file loose.
- **Bitstream survives a stereo track in between** with the native engine, which used to switch passthrough off for the rest of the session.
- **A non-retryable error moves on to the next provider** instead of failing the track.
- **Editing a track or disc number keeps its total**, and the remaining time stays right when a track repeats in the native engine.
- **The lyrics start at the top** when the next track begins.
- **A track with a long album title hid half its facts**: the facts column beside the cover sized its left half to the whole album title on one line, which pushed Released, ISRC and the UPC barcode out of the card. The left half is now capped and long values end in an ellipsis.
- **Turning on bitstream while a song plays no longer stops it**: changing bitstream, exclusive mode or the output device mid-song made mpv rebuild the output in place, which on Windows often ended the file with an error. The song now reopens where it was, and an output that refuses bitstream falls back to PCM with a warning.
- **Mornye logo on the Windows window and taskbar**: older pywebview WinForms backends ignored the icon and showed python.exe's. The window icon is now set directly (WM_SETICON) once the window is shown, at the monitor's DPI.
- **Now Playing buttons no longer cut off on Windows**: on a shorter window (Windows at 125% scaling) the cover filled the column and pushed play, previous and next half off the bottom edge. The cover now shrinks to the window height.
- **Dolby Atmos without fallback goes straight to the next provider**: with quality fallback off, a TIDAL track without Atmos used to download a stereo Hi-Res file that was then deleted, and an Atmos HTTP 502 failed the whole track before Amazon was tried. Extensions now receive `allowFallback` (tidal-web 1.2.17 stops at Atmos), and a 502 fails only that provider. A quality chosen for a single extension still steps down as before.
- **Apple Music, Tidal, YouTube and other links are accepted again**: the download pipeline only let Spotify links and known catalogue URLs through, rejecting every other link as "source not supported" before any provider was tried, although the engine reads them all. It now accepts any link the engine can read, including those an installed extension's `urlHandler` claims. Deezer playlist links are recognised, and Tidal playlist ids (UUIDs) are no longer cut down to their leading digits.
- **Retrying failed tracks no longer loops** (#284): every *Retry* added another copy of the failed tracks to the persisted `--web` queue, and the copies survived restarts. A retry now skips tracks another retry already has queued or running, a waiting retry downloads only what is still listed (so *Clear* also empties retries already queued, including ones restored after a restart), and a retry that fails again never adds a cleared track back to the list.
- **A wrong file is not fetched again from the same provider** (#284): a "Wrong track: different recording" or "Wrong duration" answer used to be retried on that provider three times, downloading the same file only to remove it again. It now moves straight to the next provider. A truncated short track is still retried, since that can be a dropped transfer.
- **M3U paths are right in a library reached through a symlink** (#277): with `~/Music/Mornye` linking to another folder, a playlist listed its own tracks as `../../other-folder/<playlist>/Track.flac`. Both paths are now resolved first, and older entries are rewritten the next time the playlist is updated, so they are repaired without being listed twice.
- **Retried playlist tracks go back to their playlist** (#277): a track that failed in a playlist and was retried from the queue panel downloaded into the bare download folder and was left out of the playlist's M3U. Failures now remember their playlist, and the retry downloads into its folder and appends to its M3U.
- **Playlist M3Us no longer point outside the library** (#277): a playlist track found in one of the *Existing library folders* (#272) was listed as `../../other-folder/Track.flac`, which Navidrome and other servers that scan only the download folder cannot follow. It is now hard-linked (or copied, across disks) into the playlist folder, still without downloading it again. Tracks shared with another playlist folder inside the library are linked where they are, as before.

- **Large subscription syncs no longer stop at 50 queued downloads** (#271): in single-user `--web` mode the download queue refused everything past 50 waiting jobs, and a followed artist's check — which had already marked those releases as seen — lost every release past the 50th while logging one error for each. Single-user mode has no cap any more; in multi-user mode scheduled checks skip the per-account pending cap (the daily quota still applies), and whatever cannot be queued is reported in one line.
- **URL handlers are anchored to the host**: an extension's `urlHandler.patterns` used to match anywhere in a URL, so `tidal.com` claimed `nottidal.com` or `https://example.org/?next=tidal.com`, and the alphabetically first extension with a broad pattern could take links meant for another. Patterns (plain hosts/paths or regexes) now must match the URL's host or a parent domain of it, the same rule everywhere a link is routed. `"enabled": false` is honoured in all three places.
- **File and folder names fit Linux filesystems**: names were never shortened, so a long title — three bytes per character in Japanese or Chinese — could exceed the 255-byte limit of ext4/btrfs (Docker volumes, most NAS shares) and fail with "File name too long" while working on macOS. Track files are now bounded to 200 bytes (leaving room for temporary names) and folders to 240, cut on a character boundary.
- **Uninstalling an extension removes its saved storage**, so a reinstall does not quietly pick up an old login.
- **Download timeout no longer kills transfers that are still progressing**: `timeout_s` used to cap the whole provider attempt, so a large Hi-Res file on a slow connection was cancelled while data was still arriving and the fallback started over on the next provider. It now bounds the time to the first byte and, after that, only stalls with no progress.
- **Short Qobuz catalogue ids resolve again**: the URL patterns demanded 9–14 characters, but Qobuz track and playlist ids are 7–9 digits in the wild, so links from the web player (`open.qobuz.com/track/8731021`) were rejected as "not supported" while albums (12–14-digit UPCs) worked. Qobuz ids are purely numeric; the patterns now accept any length, like Deezer's and Tidal's.
- Translate native Qobuz quality codes to canonical quality IDs when declared by a JavaScript extension, preventing Hi-Res requests from silently selecting CD quality.
- Restore SoundCloud URL metadata resolution by adapting JavaScript `handleUrl` track, collection, and artist responses to the downloader's `TrackMetadata` contract.
- Preserve a JavaScript extension's native `provider_id` through URL metadata so direct catalogue IDs select the extension's native lookup instead of a lossy title/artist search.
- Accept `{url, headers}` entries in `file.downloadSegments()` and keep per-segment headers across redirects, restoring SoundCloud and other byte-range HLS downloads.
- Provide the documented `ffmpeg.convert()` primitive to JavaScript extensions, restoring SoundCloud's segmented-audio remux step.
- Restore live JavaScript download progress when options follow the callback, safely deliver asynchronous callbacks from the Node reader thread, and preserve received byte counts when the transfer total is unknown.
